# Bomberman DOM

Многопользовательский DOM-Bomberman для задания 01-edu `bomberman-dom`. Проект использует игровую механику предыдущего `make-your-game` и собственный мини-фреймворк PushOK из `mini-framework`, добавляя серверное лобби, ввод никнейма, WebSocket-чат в реальном времени и синхронизированные матчи на 2–4 игроков.

## 🚀 Быстрый старт

### Требования

- Go 1.23 или новее
- современный браузер с поддержкой WebSocket, Web Worker и ES modules
- Python 3 для валидаторов репозитория
- Node.js 18+ для теста игрового движка

### Клонирование

```bash
git clone https://01.tomorrow-school.ai/git/nyestaye/bomberman-dom
cd bomberman-dom
```

### Запуск

```bash
go run .
```

Открыть:

```text
http://localhost:8080
```

Для дополнительных игроков откройте тот же адрес в другом браузере или приватном окне. На других устройствах в локальной сети можно использовать LAN-адрес, который сервер печатает при запуске.

Статический фронтенд встроен в Go-бинарник, поэтому собранный бинарник можно запускать не только из корня репозитория.

## 📝 О проекте

Обязательная часть игры использует только DOM: без canvas, WebGL и сторонних frontend-фреймворков. Интерфейс рендерится собственным PushOK из предыдущего проекта `mini-framework`.

Go-сервер управляет составом комнаты, лимитом в 4 игрока, никнеймами, таймерами лобби, чатом и игровым clock. Первый игрок остаётся authoritative host, но `GameEngine` работает внутри Web Worker и получает такты по WebSocket от сервера, а не из `requestAnimationFrame`. Поэтому симуляция не зависит от того, рисует ли браузер в данный момент вкладку хоста.

## 🎮 Игровой процесс

1. Ввести никнейм.
2. Попасть в лобби ожидания.
3. Общаться с подключёнными игроками через чат в реальном времени.
4. После подключения второго игрока начинается окно ожидания 20 секунд.
5. Если до его окончания подключаются все 4 игрока, сразу начинается 10-секундный countdown.
6. Если остаются 2–3 игрока, 10-секундный countdown начинается после 20 секунд ожидания.
7. Матч начинается, каждый игрок появляется в своём углу карты.
8. Побеждает последний оставшийся игрок.
9. Через 6 секунд после окончания матча все оставшиеся подключёнными клиенты автоматически возвращаются в новое лобби — закрывать все вкладки не требуется.

Если до старта Classic/Ghost-матча игроков становится меньше двух, таймер лобби сбрасывается.

## 💣 Механика

- 2–4 человека в обязательном multiplayer-режиме;
- 3 жизни у каждого игрока;
- фиксированные неразрушаемые стены и случайные разрушаемые блоки;
- гарантированные безопасные коридоры на старте, позволяющие выйти за радиус первой бомбы с `Flame 2`;
- взрывы в четырёх направлениях и цепная детонация;
- из разрушенных блоков могут выпадать power-up'ы;
- `Bomb` увеличивает количество одновременно установленных бомб;
- `Flame` увеличивает дальность взрыва;
- `Speed` увеличивает скорость движения;
- при потере всех жизней игрок выбывает из Classic-матча.

Управление:

- движение: `WASD` или стрелки;
- бомба: `Space` или `Enter`.

Короткое нажатие бомбы у не-хоста сохраняется до следующего 30 Hz input-пакета, поэтому быстрый тап не теряется между сетевыми выборками.

## 🎁 Бонусы

**Classic multiplayer остаётся режимом по умолчанию для обязательного аудита.** Отдельные бонусные правила выбираются на экране никнейма, а дополнительные power-up'ы и выпадение power-up после смерти также доступны в Classic, чтобы их можно было показать без переключения режима.

- **Solo / Co-op vs AI** — от одного до четырёх игроков сражаются с синхронизированным Bomber AI. Люди побеждают после уничтожения AI.
- **Дополнительные power-up'ы** — Bomb Pass позволяет проходить через бомбы, Block Pass — через разрушаемые блоки, 1UP добавляет одну жизнь.
- **Power-up после смерти** — при окончательной смерти выпадает один собранный power-up; если ничего не было собрано, выпадает случайный.
- **Team 2v2** — Team A: слоты 1 и 3, Team B: слоты 2 и 4. Взрыв союзника не наносит урон, но собственная бомба игрока по-прежнему опасна для него самого.
- **Ghost mode** — после потери всех жизней игрок становится призраком. Касание живого игрока возвращает одну жизнь, попадание призрака во взрыв окончательно выводит его из игры.

## 🌐 Мультиплеер и чат

Один WebSocket используется для событий лобби, чата, ввода игроков, серверных simulation ticks и authoritative snapshots состояния игры.

Сервер отвечает за:

- режим комнаты, выбранный первым игроком;
- проверку никнеймов;
- слоты игроков и лимит 4/4;
- счётчик игроков;
- 20-секундное ожидание;
- 10-секундный countdown;
- автоматический reset комнаты после матча;
- 60 Hz simulation ticks для текущего host;
- рассылку чата;
- определение host;
- WebSocket ping и read/write deadlines.

Worker хоста симулирует authoritative game state. Остальные клиенты отправляют input и интерполируют позиции между snapshots. Если host отключается во время матча, сервер завершает игру вместо небезопасной передачи authority клиенту, который не владел полным состоянием.

## ⚡ Производительность

Цель — требование задания о стабильных 60 FPS.

Основные решения:

- `requestAnimationFrame` используется только для визуального рендера;
- authoritative game clock задаётся сервером и обрабатывается в Web Worker;
- PushOK использует keyed DOM-ноды для игроков, бомб и пламени;
- на каждом кадре меняются только `transform`/`opacity`;
- координаты задаются процентными transform относительно размера тайла, поэтому в игровом renderer нет чтений `clientWidth` и forced layout из-за позиционирования;
- новые entities скрыты до первого установленного transform, поэтому не мигают один кадр в `(0, 0)`;
- ссылки на удалённые DOM-ноды очищаются из renderer maps;
- `will-change: transform` используется только для движущихся игроков, а не для статичных бомб и пламени;
- статическая сетка карты не перестраивается на каждом animation frame;
- canvas и WebGL не используются.

Финальную проверку FPS, frame drops, paint и layers нужно делать в Performance panel браузера на машине аудитора.

### Ручной аудит

Сначала открыть минимум две сессии браузера, затем повторить с четырьмя:

- появляется экран никнейма;
- счётчик игроков в лобби увеличивается;
- чат приходит всем подключённым клиентам;
- 2 игрока дают `20 сек → 10 сек → старт`;
- 4-й игрок запускает 10-секундный countdown досрочно;
- после конца матча подключённые клиенты автоматически возвращаются в новое лобби;
- переключение с вкладки host не останавливает симуляцию;
- каждый клиент видит всю карту;
- движение и бомбы синхронизируются;
- взрыв снимает одну из трёх жизней;
- на нуле жизней игрок выбывает в Classic;
- разрушаемые блоки исчезают;
- выпадают обязательные Bomb, Flame и Speed;
- работают бонусные power-up'ы, AI, death drops, 2v2 и ghost mode;
- Performance показывает около 60 FPS без явных frame drops;
- paint и число promoted layers остаются ограниченными.

## ⚠️ Примечания

- Classic multiplayer — обязательный режим по умолчанию. Co-op AI, 2v2 и Ghost требуют явного выбора; дополнительные bonus power-up'ы и death drops могут встречаться и в Classic.
- Authoritative simulation всё ещё выполняется браузером host в Worker; Go-сервер задаёт clock и сеть, но не реализует физику Bomberman.
- Итоговая производительность зависит от машины аудитора, поэтому Performance panel остаётся обязательной ручной проверкой перед сдачей.
